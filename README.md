# متتبّع مكاتب الخدمات العامة

أداة ويب داخلية (مستخدم واحد) تجمع بيانات مكاتب الخدمات العامة والتعقيب في المدن السعودية من
Google Places API (New)، وتعرضها في جدول لمتابعة التواصل معها عبر واتساب.

> **الإرسال يدوي دائماً.** زر «مراسلة واتساب» يفتح محادثة برسالة جاهزة فقط، وأنت من يضغط «إرسال».
> لا يوجد إرسال آلي ولا جماعي ولا جدولة رسائل، ولا زر «مراسلة الكل».

## المزايا

| الصفحة | ماذا تفعل |
|---|---|
| **المكاتب** | جدول كامل: بحث بالاسم، تصفية بالمدينة والحالة والتقييم، فرز بالتقييم وعدد المراجعات، تعديل الحالة والملاحظات وموعد المتابعة مباشرة، تصدير CSV، وزر «تحديث البيانات» لكل مكتب. |
| **متابعات اليوم** | المكاتب التي حان (أو فات) موعد متابعتها. |
| **جمع البيانات** | اختيار المدينة وعبارات البحث، تقدير عدد الطلبات قبل التشغيل، ثم عدد المكاتب الجديدة والمحدّثة. |
| **اللوحة** | لكل مدينة: الإجمالي، تمت مراسلتهم، ردّوا، مهتمون، سجّلوا، نسبة الرد ونسبة التسجيل. |
| **الإعدادات** | قالب الرسالة (بالمتغيرين `{اسم_المكتب}` و`{المدينة}`) مع معاينة، والحد اليومي. |

### ضوابط تقلل خطر الحظر

- **عداد يومي ظاهر** في أعلى كل صفحة. الحد الافتراضي 25 محادثة (قابل للتعديل). عند بلوغه يتعطل الزر حتى منتصف الليل بتوقيت الرياض. الحد يُفرض على الخادم أيضاً لا في الواجهة فقط.
- **رسالة أولى + متابعة واحدة فقط**: بعد الرسالة الأولى تصبح الحالة «تمت المراسلة» ويُضبط موعد المتابعة بعد يومين. الزر معطّل حتى يحين الموعد، وبعد المتابعة الوحيدة يتعطل نهائياً.
- **الزر معطّل** للحالات: رافض، لا تراسل، سجّل في المنصة — وللأرقام غير الصالحة (مع كتابة السبب تحت الزر).
- مع المكاتب التي ردّت أو أبدت اهتماماً يبقى الزر متاحاً لإكمال المحادثة دون تغيير حالتها (ويُحتسب في العداد اليومي).

### تحويل الأرقام

تُزال المسافات والرموز (وتُحوَّل الأرقام العربية ٠-٩)، ثم: `05XXXXXXXX` ← `9665XXXXXXXX`، وكذلك
`+966 5…` و`00966…` و`966 05…`. يُقبل فقط جوال سعودي يبدأ بـ `9665` وطوله 12 رقماً؛ غير ذلك
(أرضي، موحّد 920، رقم أجنبي، طول خاطئ) يتعطل الزر مع السبب.

## 1) إنشاء مفتاح Google Places API

1. افتح [Google Cloud Console](https://console.cloud.google.com/) وأنشئ مشروعاً جديداً (أو اختر مشروعاً قائماً).
2. **فعّل الفوترة** للمشروع: Billing ← Link a billing account. (الواجهة لا تعمل بلا حساب فوترة.)
3. **فعّل Places API (New)**: APIs & Services ← Library ← ابحث عن **Places API (New)** ← Enable.
   انتبه: ليست «Places API» القديمة.
4. **أنشئ المفتاح**: APIs & Services ← Credentials ← Create credentials ← API key.
5. **قيّد المفتاح** (من صفحة المفتاح ← Edit):
   - **API restrictions** ← Restrict key ← اختر **Places API (New)** فقط. هكذا لا يصلح المفتاح لأي واجهة أخرى لو تسرّب.
   - **Application restrictions** ← IP addresses ← أضف عنوان IP العام للجهاز/الخادم الذي يشغّل الأداة.
     (لا تستخدم HTTP referrers: الطلبات تخرج من الخادم لا من المتصفح.)
6. **اضبط حد إنفاق يومي** — بطريقتين معاً:
   - **سقف فعلي عبر الحصص (Quotas)**: APIs & Services ← Places API (New) ← Quotas & System Limits ←
     عدّل حد الطلبات اليومي لـ **Text Search** و**Place Details** إلى رقم صغير يناسبك (مثلاً 200 طلب/يوم).
     عند بلوغه ترفض Google الطلبات بدل أن تُحتسب عليك.
   - **تنبيهات الميزانية**: Billing ← Budgets & alerts ← Create budget بمبلغ شهري وتنبيهات عند 50% و90% و100%.
     (الميزانية تنبّه فقط ولا توقف الإنفاق؛ السقف الفعلي هو الحصص أعلاه.)
7. انسخ المفتاح وضعه في `.env` (الخطوة التالية). **لا تضعه في أي متغير يبدأ بـ `NEXT_PUBLIC_`** — المفتاح يُقرأ على الخادم فقط ولا يصل للمتصفح.

### عن التكلفة

كل عبارة بحث = من 1 إلى 3 طلبات Text Search (20 نتيجة لكل صفحة، حتى 60). صفحة «جمع البيانات» تعرض
التقدير قبل التشغيل. لأننا نطلب الهاتف والتقييم والموقع الإلكتروني فإن الطلبات تُحتسب ضمن فئة
**Text Search Enterprise** — راجع [صفحة التسعير](https://developers.google.com/maps/billing-and-pricing/pricing)
والحصة المجانية الشهرية. نطلب الحقول التي نحتاجها فقط عبر `X-Goog-FieldMask`.

### الالتزام بشروط Google Maps Platform

- يُخزَّن `place_id` لكل مكتب دائماً (مسموح بتخزينه بلا حد زمني).
- زر **تحديث البيانات** بجانب كل مكتب يعيد جلب بياناته من Place Details، ويُسجَّل تاريخ آخر تحديث.
- يظهر تنبيه على المكتب إذا مضى أكثر من 30 يوماً على آخر تحديث لبياناته.

## 2) التشغيل محلياً

المتطلبات: **Node.js 20 أو أحدث**.

```bash
cd tools/offices-tracker
npm install
cp .env.example .env
```

عدّل `.env`:

```dotenv
APP_PASSWORD=كلمة-مرور-طويلة-وعشوائية
GOOGLE_PLACES_API_KEY=المفتاح-من-الخطوة-السابقة
```

ثم:

```bash
npm run dev
```

افتح <http://localhost:3000> وادخل بكلمة المرور. ابدأ من صفحة **جمع البيانات**، ثم عدّل **[اسمك]** في
قالب الرسالة من صفحة **الإعدادات**.

### تشغيل نسخة الإنتاج

```bash
npm run build
npm start
```

- قاعدة البيانات ملف SQLite في `data/offices.db` (يُنشأ تلقائياً عند أول تشغيل). شغّل الأداة على جهاز أو
  خادم بقرص دائم؛ **لا تنشرها على منصة Serverless** مثل Vercel لأن الملف لن يبقى.
- النسخ الاحتياطي: أوقف الخادم وانسخ مجلد `data/` كاملاً (يشمل ملفات `-wal` و`-shm`).
- تغيير `APP_PASSWORD` يُبطل كل الجلسات المفتوحة فوراً.

### أوامر التطوير

| الأمر | الوظيفة |
|---|---|
| `npm run dev` | خادم التطوير |
| `npm run lint` | ESLint |
| `npm run typecheck` | فحص TypeScript |
| `npm test` | اختبارات Vitest (تحويل الأرقام، رابط واتساب، الحد اليومي وقواعد المتابعة) |
| `npm run build` | بناء الإنتاج |

## البنية

```
app/
  (app)/            صفحات الأداة (المكاتب، اليوم، الجمع، اللوحة، الإعدادات)
  login/            صفحة الدخول
  api/              واجهات الخادم (collect, offices, contact, refresh, settings, counter, export)
components/         الجدول، زر واتساب، العداد اليومي، الإشعارات
lib/
  phone.ts          تحويل الأرقام السعودية
  whatsapp.ts       القالب ورابط wa.me
  outreach.ts       الحد اليومي وقواعد المتابعة (مصدر واحد للواجهة والخادم)
  places.ts         عميل Google Places (على الخادم فقط)
  db.ts             SQLite
  session.ts        كوكي الجلسة الموقّع (HMAC-SHA256)
  messages.ts       كل نصوص الواجهة
middleware.ts       يحمي كل الصفحات والواجهات بكلمة المرور ويرفض الطلبات من مصادر أخرى
tests/              اختبارات Vitest
```
